## 0. 通用约定

| 项 | 约定 |
|---|---|
| 基址 | 同源相对路径 `/api/*`，**不要写绝对 URL**，不要 CORS，不要 CDN |
| 成功 | **新加的端点**用 `{"ok": true, "data": {...}}`；**既有端点保持原样**（裸对象），不要改它们的形状——改了会打破既有 50 条验收判据与旧前端 |
| 失败 | `{"ok": false, "error": "人话说明"}`（HTTP 状态码仍按语义给） |
| 列表 | `{"ok":true,"data":{"items":[...],"total":N}}`，**分页字段统一 `page` / `size` / `total`** |
| 时间 | 一律 `"YYYY-MM-DD HH:MM:SS"` 本地时间字符串 |
| 中文 | 请求/响应 `application/json; charset=utf-8`；**文件名下载走 RFC 5987** |

> 前端已写 `unwrap()` 同时兼容「裸对象」和「`{ok,data}`」两种信封，
> 所以后端**新增**端点统一用 `{ok,data}` 即可，既有端点**不要动**。

### 0.1 鉴权（新增，P2）

登录后拿到的 `token` 放请求头 `X-Auth-Token`。**两道锁**（沿用 2026-10-22 定下的规矩）：

- 界面层：非管理员的前端**根本不渲染**管理入口
- 接口层：管理端点一律 `require_admin`，手工构造请求也只得到 `403`

未登录访问受保护端点 → `401 {"ok":false,"error":"请先登录"}`。

**本机默认免登录**：`config.json` 里 `auth.enabled=false`（默认）时，所有人视为
`admin` 免登录身份，方便本机演示；`auth.enabled=true` 时才走真实账号体系。
→ **`/api/auth/me` 在免登录模式下也要返回 `{"ok":true,"data":{"user":{"username":"…","role":"admin"}}}`**，
不能返回 404：前端靠它决定要不要渲染「提案与审核」区块。

### 0.2 「仅本机」端点的判断规则（**别写错**）

`/api/health/detail`、`/api/diagnose` 这类含本机绝对路径的端点**只能本机访问**。
判断**不能只看 `request.client.host`**——在 Cloudflare Tunnel / 反向代理后面，
uvicorn 看到的直连方是**代理进程自己**（隧道走本机回环），`client.host` 恒为 `127.0.0.1`，
拿它判断等于**这个限制根本没生效**。

正确规则（`app.py` 的 `_is_local_request` 已实现）：

1. 直连方地址**必须**是回环地址（`127.0.0.1` / `::1` / `localhost` / `127.*`）
2. **且**没有转发头，或转发来的地址（`CF-Connecting-IP` / `X-Real-IP` /
   `X-Forwarded-For` 的第一个）也是回环

→ 隧道进来的公网访客：直连方回环 ✓、转发头是公网 IP ✗ → **403**
→ 外网直连：直连方是公网 IP ✗ → **403**
→ 本机直接访问：✓ → 放行

另有一道总闸：`config.json` 的 `app.local_detail`（默认 `true`），
挂公网时置 `false` 可把这类端点整体关掉。

**验收方式**：跑 `python 01-程序/_tools/audit_exposure.py`，
它会做两遍探测——普通匿名 + **「隧道视角」**（带 `CF-Connecting-IP: 203.0.113.7`）。
隧道视角下本机端点必须全部 401/403。

{"ok":true,"data":{

            "weight":2,"degree":37,"x":-123.45,"y":678.90}],
  "edges":[{"src":"lit:LIT-000001","dst":"img:IMG-…","rel":"contains","lit_id":"LIT-000001","weight":1}],
  "stats":{"nodes":3491,"edges":31876,"returned_nodes":600,"returned_edges":7140,

                "tagged":"文献标注标签","imgtag":"图像标注标签","cocite":"共享标签"}

## 2. F3 导入导出（后端新增）

### 2.1 `POST /api/import/preview`（multipart）

- 表单字段：`file`（xlsx 文件，必填）、`kind`（`literatures` | `images`，必填）
- **只做预检，不写主库**。返回逐行 diff：

```json
{"ok":true,"data":{
  "staging_id":"IMP-20261028-0001",
  "kind":"literatures",
  "filename":"文献基本信息登记表_修复.xlsx",
  "columns_found":34,
  "columns_expected":34,
  "missing_required":["题名*"],
  "unknown_columns":["我加的一列"],
  "summary":{"rows_total":200,"rows_new":3,"rows_changed":12,"rows_same":185},
  "diffs":[
    {"target_id":"LIT-000123","op":"changed",
     "fields":[{"col":"题名","old":"旧题名","new":"新题名","required":true},
               {"col":"出版年","old":"2020","new":"2021","required":false}]}
  ],
  "note":"预检不写主库；确认后在「提案与审核」里逐条批准。"
}}
```

- `op` ∈ `new`（新记录）/ `changed`（有字段变化）/ `same`（无变化）
- **列名按名字匹配**（不是按列序），`*` 是必填标记不是列名的一部分
- 表头行**自动定位**：在前面 10 行里找最像表头的那行（依据 `lzkg/schema/registry_columns.json` 的列名集合）
- 缺必填列 → 直接 `400`，`error` 里说清缺哪几列
- **预检时把有变化的行写进 `staging` 表**（`status='pending'`），返回 `staging_id`

### 2.2 `POST /api/import/apply`

- Body：`{"staging_id":"IMP-…","target_ids":["LIT-000123", ...]}`
- `target_ids` 为空 → 批准该批次全部 pending 行
- 把批准的行写进 `literatures` / `images`，同步更新 `meta` 的计数
- 返回 `{"ok":true,"data":{"applied":12,"batch":"IMP-2026…","log_id":7}}`

### 2.3 审核面板（提案—审核制）

| 端点 | 方法 | 说明 |
|---|---|---|
| `GET /api/staging?status=pending&kind=&page=1&size=50` | GET | 待审列表，`data.items[]` 含 `id/kind/target_id/proposer/status/created_at/diff` |
| `POST /api/staging/{id}/approve` | POST | body `{"reviewer":"…","note":"…"}` → 写主库 |
| `POST /api/staging/{id}/reject` | POST | body `{"reviewer":"…","note":"…"}` → 只标状态，不写主库 |
| `GET /api/import/log?page=1&size=50` | GET | 导入历史（`import_log`） |

**已完成的审核记录不删除**，只改 `status`（`pending` → `approved` / `rejected`），
`reviewer` / `review_note` / `reviewed_at` 落库。

### 2.4 导出

| 端点 | 说明 |
|---|---|
| `GET /api/export/literatures.csv` | 已存在 |

## 3. P2 扩展项

### 3.1 登录与账号

| 端点 | 方法 | 请求 | 响应 |
|---|---|---|---|
| `POST /api/auth/login` | POST | `{"username":"…","password":"…"}` | `{"ok":true,"data":{"token":"…","user":{"username":"…","role":"admin"}}}` |
| `POST /api/auth/logout` | POST | — | `{"ok":true}` |
| `GET /api/auth/me` | GET | — | `{"ok":true,"data":{"user":{"username":"…","role":"admin"}}}`，未登录 401 |

- 密码哈希用 `hashlib.scrypt`（标准库，零依赖），格式 `scrypt$n$r$p$salt$dk`
- 默认账号：见 `config.json` 的 `auth.bootstrap`（默认用户名 `admin`、密码 `CHANGE-ME-AT-FIRST-LOGIN`），**首次登录后必须提示改密码**
- `POST /api/auth/password` body `{"old":"…","new":"…"}` → 改密码

### 3.2 收藏

| 端点 | 方法 | 说明 |
|---|---|---|
| `GET /api/favorites` | GET | `data.items[]` = `{lit_id, title, note, created_at}` |
| `POST /api/favorites/{lit_id}` | POST | body `{"note":""}` → 收藏 |
| `DELETE /api/favorites/{lit_id}` | DELETE | 取消收藏 |

### 3.3 在线录入（提案式）

- `POST /api/entry` multipart 或 JSON，字段同登记表的列（按**列名**给，不按列序）
  - → 写入 `staging`（`kind='literatures'`，`status='pending'`，`proposer`=当前用户）
  - **不直接写主库**——这正是「提案—审核制」的含义
  - 返回 `{"ok":true,"data":{"staging_id":123,"status":"pending"}}`
- 前端在「文献」页放一个「＋ 录入一条」入口，填完提交后提示「已提交，等待管理员审核」

### 3.4 时间线与统计

| 端点 | 说明 |
|---|---|
| `GET /api/stats/timeline` | `data.periods[]`（分期）、`data.years[]`（出版年）、`data.doc_types[]` |
| `GET /api/stats/region` | 各空间分区文献数 |
| `GET /api/stats/map.png` | **后端离线出图**（matplotlib，PNG）。有坐标就画点位，没有就画分区柱状图。返回 `image/png` |
| `GET /api/sites` | 遗址点位表（从 `data/遗址点位表.xlsx` 读），`data.items[]` = `{site_name, lat, lon, source_lit_id, note}` |

> **坐标不编造**：`data/遗址点位表.xlsx` 是空表 + 候选清单，等人工补坐标。
> 在坐标补齐前，`/api/stats/map.png` 自动退化为「空间分区文献数」柱状图，
> 并在图上注明「坐标待补，当前显示分区统计」。

### 3.5 AI 问答

`POST /api/ai/ask` body `{"question":"…","top_k":5}`

```json
{"ok":true,"data":{
  "answer":"…",
  "citations":[{"lit_id":"LIT-000001","title":"…","snippet":"…"}],
  "provider":"openai-compatible",
  "degraded":false
}}
```

**没有配置 API key 时不许报错，也不许编答案**：
- `config.json` 的 `ai` 段：`{"enabled":true,"api_base":"…","api_key":"…","model":"…"}`
- 未配置 key → **降级模式**：`degraded=true`，`answer` 由本地 FTS5 检索结果拼成
  （「检索到 N 篇相关文献，主要内容摘要如下：…」），**必须明确写明这是检索结果、
  不是大模型生成的回答**
- 配置了 key → 走 OpenAI 兼容接口，把检索到的片段作为上下文喂进去，
  要求模型**只依据给定片段作答并给引用**；`citations` 返回实际引用的文献

## 4. P3 体检

- `GET /api/health` → `{"ok":true}`（**已脱敏**，公网可访问，不泄露路径与计数）
- `GET /api/health/detail` → **仅本机**（`request.client.host` 是 127.0.0.1/::1 才放行），
  返回：库路径、源路径、各表计数、布局版本、依赖版本、磁盘占用、上次迁移时间
- `GET /api/diagnose` → 一组**可执行的**体检项（每项带 `ok` / `detail` / `fix`）：
  库是否存在、源目录是否可达、登记表指针列是否都指向存在的 MD、FTS 是否可检索、
  布局坐标是否齐全、模板与登记表列是否一致

## 6. 已知的坑（别再踩一遍）

| 坑 | 说明 |
|---|---|
| `.cmd` 正文 | 必须纯 ASCII + CRLF，**不能有裸括号**（`echo 02*(...)` → cmd 崩） |
| HTTP 头 | 不能放中文文件名 → RFC 5987 `filename*=UTF-8''…` |
| f-string 嵌 JS | Python f-string 里写 JS 花括号会炸 → JS 单独拼字符串再拼进去 |
| 静默 except | `except Exception: pass` 会把「读失败」伪装成「进程结束」 |
| 扫描顺序 | SQLite 无 `ORDER BY` 时扫描顺序会变 → **Louvain / spring_layout 结果会变** |
| set 迭代序 | Python 字符串哈希每进程随机 → `G.subgraph(set)` 顺序不稳 → 坐标不可复现 |
| 指针列 | 登记表 col19 指向的产物类型必须与下游要的一致（指错 = 静默漏数据） |
| doclib 短 ID | 长度不固定（7/8 位都有）→ 正则用 `doc:([0-9a-f]+)`，别写死位数 |
| `%TEMP%\bisect.py` | 顶掉标准库 → 本项目脚本一律放独立目录 |
