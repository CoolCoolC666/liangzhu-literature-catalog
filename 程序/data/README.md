# `程序/data/` —— 运行时数据与配置说明

> ★ 本目录在**公开仓库里只有「可公开的那部分」**：坐标台账、受控词表、离线底图。
> **没有数据库**，因为库里有 CNKI 机构订阅的文献全文与原始 JSON，
> 按「机构订阅取得的文献不得公开外传」不能公开。

## 一、自己填配置

程序第一次启动会在程序根目录生成 `config.json`（**它已被 .gitignore 排除**，别提交）。
想手动改，照这个结构来（可参考 `程序/config.example.json`）：

| 段 | 键 | 说明 |
|---|---|---|
| `app` | `host` / `port` | 默认 `127.0.0.1:8771`。**别改成 0.0.0.0** |
| `app` | `local_detail` | 本机诊断端点是否暴露（含绝对路径），公网必须 `false` |
| `source` | `root` | 你的 `04_专题研究` 目录；也可以用 `python -m lzkg set-source "<目录>"` |
| `db` | `path` | 库文件位置，默认 `程序/data/lzkg.db` |
| `auth` | `bootstrap` | 首次启动的管理员账号与**初始口令** —— **务必改掉** |
| `public` | `access_aud` / `access_app_id` / `access_team_domain` | 你自己的 Cloudflare Access 应用信息（用占位符，部署时填） |
| `public` | `domain` | 你的公网域名 |
| `webdev` | `enabled` | 「Web Dev 浏览数据同步」总闸 |
| `browse_server` | `enabled` | 「浏览记录存本站服务器」总闸 |

★ **各人的 AI key / WebDAV 密码 / MinerU token 不要写进 config.json** ——
它们存在**使用者自己的浏览器**里（localStorage），服务端不保存。

## 二、重建数据库

```powershell
python -m lzkg set-source "<你的 04_专题研究>"
python -m lzkg migrate        # 幂等：可重复跑
python -m lzkg stats          # 看建了多少
```

`migrate` 会连带算好图谱布局坐标，所以新环境打开图谱页就是固定坐标，不用等力导向重排。

## 三、这个目录里各文件是什么

| 文件 | 是什么 | 能公开吗 |
|---|---|---|
| `遗址坐标.json` | 机读坐标（4 个点 + 遗址群范围框），每条带出处 | ✅（事实性数据） |
| `坐标证据台账.txt` | 每条坐标的出处与原文摘录 | ✅ |
| `遗址点位表.xlsx` | 点位表（**空坐标**）+ 区域代表点 + 文献坐标三个工作表 | ✅ |
| `受控词表-码位对照.txt` | 受控词唯一码位表 | ✅ |
| `controlled_vocab*.json` | 受控词表本体 | ✅ |
| `basemap/` | 离线底图 GeoJSON | ✅（Natural Earth 公共域 + OSM ODbL） |
| `lzkg.db` | **数据库**（全文 + 原始 JSON + 成员与浏览记录） | ❌ **不入库** |
| `record/` | 服务器端浏览记录（按身份分目录） | ❌ **不入库** |
| `*.log` `*.pid` | 运行痕迹 | ❌ **不入库** |

## 四、坐标这件事的纪律（别改坏）

- 坐标**以文献为准（WGS84）**；高德 GCJ02 / 百度 BD09 有几百米系统误差，**不得冒充**。
- **18 个单遗址的实测坐标在文献里没有** —— 检索过 203 篇全文与 202 份解析结果，
  公开检索也没找到。表里**保持为空**并写明原因，**不推测填充**。
- **区域代表点是区块统一坐标**（示意精度约 ±1.1 km），**不是遗址实测坐标**。
- **主题类分区不配点**（数字化 / 文化创意 / 参考案例 / 跨遗址）。
