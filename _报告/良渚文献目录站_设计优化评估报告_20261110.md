## 二、资料的核心主张，与本站现状逐条对照

### 2.1 「AI 味」到底是什么

资料 B/C/D 一致指向同一组特征：蓝紫渐变、大圆角容器、emoji 充当正式图标、左右固定分栏、抽象晦涩文案、解释性文字塞满页面、多套方案只换图标与配图。

> **机制解释**（C 原文）：大模型预测的是「最可能出现的下一个 token」，未经约束时必然收敛到「平均值」。所以破法不是要求「更有创意」，而是**改变它选择答案的条件**——用外部约束制造多样性、用具体视觉概念替代抽象形容词、删掉无用元素。

### 2.2 本站实测：是不是「AI 味」？

用脚本对前端文件做全量静态扫描（CSS 23,762 字符 / 281 条规则；JS 237,868 字符 / 237 个函数 / 33 个视图渲染函数）：

| AI 味特征 | 本站实测 | 判定 |
|---|---|---|
| 大面积圆角容器 | `border-radius` 82 处，取值集中在 **4px(7) / 5px(13) / 6px(18)**，仅 6 处 `50%` | ✅ 克制（且视觉方案已把圆角收到 2px，见「壁纸」样式） |
| 蓝紫渐变铺满 | `linear-gradient` 6 处、`radial-gradient` 0、`conic-gradient` 0 | ✅ 无滥用 |
| 玻璃拟态 / 泛光 | `backdrop-filter` 0、`filter` 2 | ✅ 没有 |

## 三、结论摘要

1. **不要照抄资料 A 的做法。** 它的核心手段（外链 Google Fonts、CDN 素材、HLS 视频背景、Next.js/Tailwind/shadcn 栈、生成视频做 hero）在本站全部不可用：零外链是硬约束、断网必须可用、组内包已 141.5 MB、卫星影像授权尚未核实、前端通篇 ES5 且不新增依赖。**可借的只有「把参考风格拆成设计系统再落地」这一步。**
2. **本站的真实问题不是「AI 味」，而是「没有质感、没有反馈、没有无障碍」。** 三个最硬的缺口：零动效、零可访问性、视觉锚点缺失。
3. **最值得投入的一条不是改样式，是建立评审机制。** 资料 C/D 反复强调「自己评自己不算数」。本站所有设计决策目前都由同一实现者闭环，风格方案已定死「工程图纸」，再往下走容易越修越偏——**一个不看代码的盲评子代理，是继续打磨前最该补的基础设施**。
4. ~~**本次截图暴露了一个疑似布局溢出问题**（两页右侧被裁），优先级高于任何视觉调整，须先查清。~~
   **〔已订正 2026-11-10〕** 实测四档视口后确认：**不存在横向溢出**（`scrollWidth == clientWidth`，超宽元素 0 个），
   「被裁」是截图按设备像素输出造成的观感错觉；真正的问题改成了**版心不一致**（顶栏 1240 居中 vs 正文全宽），
   已修（见 P0-2），并补了 3 项判据防回归。

## 四、优化清单（按优先级）

> 每条格式：**证据 → 做法 → 与硬约束的兼容性 → 工作量 → 验收判据**
> 建议实施节奏遵循既有惯例：**先做单页样例版 → 用户确认 → 再推广**（与《视觉风格方案》的推广方式一致）。

### P0-1　全站补一层「克制的过渡反馈」（动效）

- **证据**：`transition` 0 次、`@keyframes` 1 次；资料 A/C 都把「自然动态」列为去模板感的关键。
- **做法**：只加**功能反馈级**动效，不加表演性动画——
  ① 页签/路由切换时内容区 120ms 淡入上移 6px；
  ② 按钮/卡片 `:hover` 150ms 背景与边框过渡；
  ③ 弹层（灯箱 `#lb`、模态 `.modal`）150ms 透明度过渡；
  ④ 列表加载时用已有 `showLoading` 状态做骨架/占位过渡（现有 25 处 loading 逻辑，缺视觉过渡）。
  **一律只用 `transform` / `opacity`，不触发 layout**。
- **兼容性**：纯 CSS，零外链、零依赖、ES5 安全；不违反任何硬约束。
- **工作量**：约 30 行 CSS + 4 行 JS（view 切换处加 class）。
- **验收判据**：`tests/` 新增「关键交互元素带 transition 且只含 transform/opacity」的静态断言 + 真实浏览器点一遍确认不卡顿。

### P0-2　查清并修掉横向溢出（疑似真 bug）　★〔已订正 2026-11-10：不是溢出，是版心不一致；已修〕

> **订正说明**：原判断「横向溢出」**不成立**。本轮用临时测量探针在真实浏览器里量了四档视口
> （885 / 1265 / 1646 / 1885 **CSS 像素**），总览页与图版页的 `scrollWidth` **始终等于** `clientWidth`，
> 超宽元素计数 **OVER=0**，四档都没有横向滚动。
> 原述里的「右侧被裁」是**截图观感**：截图按设备像素输出、页面按 CSS 像素布局，
> 两套坐标不是一回事（同一窗口截图宽 1909 设备像素 ≈ 1365 CSS 像素），所以看起来像被切。
> **真正存在并已修掉的是另一件事 —— 版心不一致**：`.wrap`（1240 居中）只包了顶栏与页脚，
> `main` 却是全宽，于是宽屏上顶栏标题与正文左缘差 **203 px（1646 宽）/ 322 px（1885 宽）**。
> **已修**：`main` 加 `max-width:1240px;margin:0 auto`，顶栏 / 正文 / 页脚三处版心统一，
> 左缘实测差 **0 px**（30 / 221 / 340，三者相等）。
> **原述保留如下**：

- **证据（原述）**：本次真实截图 1661 px 宽下——总览页右端 KPI 卡「201 可全文…」被切；图版检索页顶栏「自动同步：」被切、页头「覆盖 17…」被切、检索行「复核状态只作显示，不…」被切。
- **现状未知（原述）**：`body`/`html` 没有 `overflow-x:hidden`，`.wrap` 只有一条 `max-width:1240px` 规则，说明溢出元素不是 `.wrap` 本身撑开，**需要实测定位是哪个子元素**（本页截图是全页宽度，视口更窄，故溢出量不可从截图直接读出）。
- **实际做法（本轮落地）**：① 临时往页面里注入一段测量探针，把 `clientWidth / scrollWidth` 与所有
  `right > clientWidth` 的元素（tag + class + 宽 + 左右边界）直接打印出来，定位完即删（已删净，`TEMP-OVF` 残留 0）；
  ② 用 **iframe 模拟宽视口**（iframe 内 `clientWidth` = iframe 宽度，媒体查询按 iframe 宽度生效），
  在 885 / 1265 / 1646 / 1885 四档下取真值，不靠肉眼估；
  ③ 结果：溢出元素 **0 个**；真问题是 `main` 缺版心 → 加 `max-width:1240px;margin:0 auto`；
  ④ 顺带确认 `footer > .wrap` 本来就限宽，所以只有 `main` 漏了。
- **兼容性**：纯 CSS 一行修正，不新增依赖、不影响零外链与 ES5 约束。
- **工作量**：已实做（定位 + 修正 + 回归）。
- **验收判据（本轮落地）**：`tests/test_all.py` 新增 **3 项**
  「正文主区有版心限宽（实测 1240px）」「顶栏与正文版心同宽（宽屏上左右边缘对齐，实测差 0px）」
  「正文主区水平居中（margin:0 auto）」；浏览器实测四档视口 `scrollWidth == clientWidth`、超宽元素 0 个。

### P0-3　补可访问性基线（键盘 / 语义 / 动效偏好）

- **证据**：`tabindex` 0、`role` 1、`aria-label` 1、`focus-visible` 1；`button` 82 个、`input` 54 个、`select` 17 个；`prefers-reduced-motion` 0；`dialog` 0（灯箱 `#lb` 无 `role="dialog"`）。
- **做法**：① 全局补 `:focus-visible` 可见焦点环（陶土色 2px outline），去掉默认 outline 的场景要保证替换而非删除；② 图标按钮补 `aria-label`（现有 `title=` 9 处不足以覆盖 82 个按钮）；③ 灯箱加 `role="dialog" aria-modal="true"` + `Esc` 关闭 + 焦点回到触发元素；④ 表单控件与 `label` 关联（已有 39 个 `<label>`，需补齐遗漏的 `for`）；⑤ 加 `@media (prefers-reduced-motion: reduce){ *{transition:none!important;animation:none!important} }`。
- **兼容性**：纯 HTML 属性 + CSS，无依赖。
- **工作量**：约 1–2 h（可脚本批量补 aria-label，逐个复核）。
- **验收判据**：新增判据「所有 `button` 有可访问名称」「`#lb` 有 `role=dialog`」「存在 `prefers-reduced-motion` 降级块」「存在 `:focus-visible` 规则」；键盘 Tab 一圈能走通主流程。

### P0-4　把 171 处提示文案重新分层（减法，不是删文案）

- **证据**：提示/口径类文案 171 处，散落在控件区、页头读数区、空状态区；截图里「关键词与类别同时生效（AND）…」这类说明与操作控件同一视觉层级，用户容易把说明当按钮。
- **做法**：① 建立三级语义：**常驻读数**（数据口径，页头等宽区）／**就地提示**（控件下方 12px 弱文）／**按需解释**（`title` / `?` 展开，默认不显示）；② 把解释性长句从控件旁移到「口径条」或详情页脚注；③ 同一控件旁最多保留一句说明，其余合并；④ 文案全部保留（口径透明是本站特色），只改层级与位置。
- **兼容性**：纯前端改动。
- **工作量**：约 2–3 h（需逐页过一遍 33 个视图函数）。
- **验收判据**：判据新增「控件区内说明文字长度上限」与「口径条存在性」断言；真实浏览器确认读数不被说明淹没。

### P1-1　建立「设计盲评子代理」评审机制 ★ 方法性最高价值

- **证据**：资料 C/D 的核心结论——执行者评自己的实现会被历史包袱绑架（「史上雕花」）。本站现状：全部设计决策由同一实现者闭环，无任何外部视角。
- **做法**：
  ① 把资料 D 的 `references/review-and-media.md` 评审提示词固化为本项目的一份评审协议（放到 `01-程序/_docs/` 或 `02-报告/`）；
  ② 用独立子代理（无本会话历史的新上下文）**只给截图 + 目标用户/任务 + 审美 brief**，不给代码、不给实施难度、不给历史解释、不给目标分；
  ③ 评审维度固定：整体构图 / 信息层级 / 字体 / 色彩 / 间距 / 图像整合 / 细节一致性 / 主任务是否清楚；输出**最多 3 个最有影响的问题**（位置 + 表现 + 影响 + 可执行建议）+ 0–10 分完成度；
  ④ **每轮只改最影响效果的 1–3 个问题**，改完重新截图再评，**最多两轮**；不收敛就报剩余缺口，不追分。
- **兼容性**：不涉及产品代码；评审结论不得直接当验收依据（与 D 自述一致）。
- **工作量**：写协议 0.5 h；每轮评审 0.5 h。
- **验收判据**：至少完成一轮真实盲评并产出「3 个最影响的问题 + 改动前后截图对照」。

### P1-2　给无图页面补视觉锚点（用已有的 3162 张图版）

- **证据**：图版检索页有实物图，质感在线；但总览页、文献列表页、统计页全是数字与色条——资料 C 说「只让 AI 输出 HTML/SVG/文字，通常得到结构完整但视觉单薄的页面」。
- **做法**：不生成新素材（零外链、授权风险），**直接用库内已有图版**做锚点：① 总览页顶部放一条「本库文物图版横带」（4–6 张缩略 + 编号），替代纯数字首屏；② 文献详情页图版区已有图版，列表页可给前 1–2 张缩略；③ 统计页用图版构成的纹理底或「本库图版类型占比」实物拼图代替纯色条。
- **兼容性**：图版已在数据包内（组内包），不新增体积；公开版按现有白名单机制处理。
- **工作量**：约 2 h（需确认图版图在列表页的取图接口是否已存在——`/api/images` 已有，图版页在用）。
- **验收判据**：截图证据 + 断网可用性复测。

### P2-1　储备第三个视觉方向（用随机种子发散，不盲改）

- **做法**：按资料 A/C，用本地随机种子（`python -c "import secrets; print(secrets.token_hex(48))"`）派生一份视觉意向（节奏 / 分组 / 对比 / 材质），做成「壁纸 3」的**概念稿**（不写代码），与现有「原版 / 壁纸墨绿」并列为可选项。**种子只用于探索，不进产品、不写进文档正文。**
- **注意**：方向差异必须体现在构图、信息组织、字体与交互隐喻上，**不能只换颜色**（资料 C 反复强调）。
- **工作量**：概念稿 1–2 h；是否落地由用户拍板。

### P2-2　字体层级再挖一档（不引外链）

- **做法**：保持「Windows 必然有族」约束，把标题从「更大更粗」推进到「族 + 字距 + 字重 + 字号」四件套：标题用 `Microsoft YaHei` 的 700/900 + `letter-spacing` 拉开；数字统一 `font-variant-numeric: tabular-nums`（方案里已写，但需确认全站落地）；英文小标继续用等宽 `Consolas` 形成双层节奏。
- **兼容性**：零外链，无新增依赖。
