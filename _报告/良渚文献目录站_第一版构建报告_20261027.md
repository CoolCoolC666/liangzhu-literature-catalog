## 一、看懂：一个网站怎样运行

课件目标 01 要求「解释一个网站怎样运行 —— 浏览器、服务器、文件各管什么」。本项目的实际形态：

```
浏览器（index.html，单文件，零 CDN）
   │  同源 fetch /api/*        ← 浏览器只管「发请求、画界面」
   ▼
FastAPI（lzkg/app.py，uvicorn 跑在 127.0.0.1:8771）
   │  查表、算指标、拼 JSON     ← 服务器只管「取数、算图、给结果」
   ▼
SQLite（data/lzkg.db，单文件）
   │                          ← 文件只管「存数据、给索引」
   ├─ literatures / images / tags / lit_tags / img_tags
   ├─ docs_fts / raw_json_fts  ← FTS5 trigram 全文索引
   └─ graph_nodes / graph_edges ← 图谱节点与边
```

三句话讲清分工：

- **文件管「事实」**：登记表里写了什么，库里就是什么，一个字段都不改写。
- **服务器管「取数与算」**：多轴筛选、两个口径的图指标、Louvain 社区，都在这一层现算。
- **浏览器管「呈现与交互」**：拿到 JSON 画列表、画图、标黄命中词、点边弹证据。

**一次请求的完整链路**（以「检索 玉琮」为例）：

```
用户在检索页输入「玉琮」
  → GET /api/literatures?q=玉琮&size=20
  → 词长 2 < trigram 阈值 3 → 整条查询退回 LIKE 扫描 docs_fts.content
  → 命中 67 篇，片段从 MD 正文里截取（substr + instr 定位命中窗口）
  → 前端渲染 20 条/页，命中词标黄
```

**为什么必须这样**：SQLite 的 FTS5 trigram 分词器要求查询词 **≥ 3 个字符**，查「玉琮」会命中 **0** 条。
所以规则是：**只要有一个词短于阈值，整条查询退回 LIKE**，不能半边走索引半边扫描——那样会漏结果。
实测：2 字「玉琮」走 LIKE 命中 **67** 篇；3 字「良渚古城」走 FTS5 命中 **77** 篇。

## 二、说清：把「想要」写成能执行的条件

课件目标 02 要求「向 AI 描述可实现的网站需求 —— 把『想要』写成能执行的条件」。

本项目的做法是**先冻结契约，再并行开发**。契约在 `01-程序/_docs/数据契约.md`，把「想要」拆成三张可验证的表：

| 层 | 想要什么 | 写成什么 | 怎么验 |
|---|---|---|---|
| 数据 | 「把登记表搬进库」 | 8 张表、每张表的列、列的来源列号、FTS5 外部内容模式、标签规范化的 6 条规则 | `tests/test_all.py` 断言 **条数等于实测真值**（200 / 3162 / 120 / 202） |
| 接口 | 「四个功能能调」 | 15 个 HTTP 端点的参数、响应字段、两个口径必须同时出现 | 同上，API 部分 18 项 |
| 界面 | 「能看」 | 5 个页签、零外链、命中标黄、点边出证据、两处口径 | 真实浏览器逐页核对 + 前端自建 Node+DOM 桩测两种模式 |

**契约带来的直接收益**：前后端可以**并行写**。前端 Agent 写完后主动回报了 **6 处与后端的接口落差**（其中 1 处是真 bug：它按 `../04_专题研究/` 拼图片路径，而浏览器读不到服务根目录外的文件），后端据此补了 `/media/img/{filename}` 代理端点，契约同步更新。

**写需求的一条纪律**：判据一律写「**必须等于某个实测真值**」，不写「不为空」。

> 这条不是教条，是从 `cacx` 的教训继承来的：它当年 1 311 条关系里有 417 条（31.8%）证据挂错，
> 而测试是**绿的**——因为测试只断言「证据句是原文的连续片段」，而标题本来就是原文片段。
> **断言「产物合法」不等于断言「产物正确」。** 那次缺陷是「核对文档时顺手点了一条边」发现的，不是靠测试。

## 三、做出来：建了什么，怎么验的

### 3.1 数据迁移（本项目的核心）

| 目标表 | 条数 | 来源 | 说明 |
|---|---|---|---|
| `literatures` | **200** | 文献基本信息登记表（34 列） | **全量**，含「来源判据（痕迹）」「开放类型/使用条件」等关键列 |
| `images` | **3 162** | 文献图像信息登记表（26 列） | **全量**，含图注、页码、对象类型、四维标签、复核状态 |
| `tags` | **120** | 四维标签 + 图像类型 + 对象类型 | **规范化**后（见 §3.2） |
| `lit_tags` / `img_tags` | 923 / 21 116 | 标签关联 | |
| `raw_json` | **202** | `02_解析结果/MinerU_json_LIT-*.json` | **4.0.12 原件全文入库，可检索** |
| `docs_fts` | **201** | `03_文献全文/*.md` | FTS5 trigram 索引 |
| `graph_nodes` / `graph_edges` | 3 491 / 31 876 | 两张表 JOIN | **零抽取** |

迁移**只读源文件**，不删不改 `04_专题研究` 下任何东西；幂等，可重复跑（17~22 秒）。

**一个工程决策**：原始 JSON 有 113 MB。如果「既存表又建独立 FTS 索引」，
同样的正文会有两份 → 库膨胀到 **560 MB**。改用 FTS5 的**外部内容模式**
（`content='raw_json', content_rowid='rowid'`），索引只存倒排 → **318 MB**，
省下 113 MB 且检索行为不变。

### 3.2 ⭐ 最重要的一个发现：四维标签的「代码」是族系代号，不是标签代号

建图前必须处理标签。规范化做了四件事：拆多值 → 拆「代码/名称」→
括号限定后缀不进 name → **一码多义的码位标记为不可靠**。

第 4 条是**实测出来的，不是设计出来的**。我原本只防了 `R-0199`（空间分区里塞了 9 个不同名称），
但一查全表发现：

| 维度 | 码位 | 名称数 | 例子 |
|---|---|---|---|
| topic | `S-0802` | **18** | 文物研究 / 治理路径 / 纹饰研究 / 聚落考古 / 学术史 / 植物考古 / 科技考古 / 宗教考古 / 丧葬考古 / 祭祀考古 / 建筑技术 / 玉器研究 / 墓葬考古 / 环境考古 / 水利工程 / 社会考古 / 人骨考古 / 水利与环境 |
| topic | `S-0801` | **11** | 数据库 / 考古发掘 / 保护 / 综述 / 考古研究 / 方法研究 / 空间分析 / 墓葬 / 祭坛遗址 / 玉器 / 遗址调查 |
| topic | `S-0803` | **9** | GIS / 数字化 / AIGC / 遥感 / VR / 数字传播 / 数字化保护 / 建筑研究 / 数字化传播 |
| region | `R-0199` | **8** | 浙江综合 / 中国综合 / 文化创意 / 良渚博物院 / 环太湖 / 良渚全域 / 数字化 / 良渚遗址群 |
| topic | `S-0804` | **8** | 活化 / 信息系统 / 人机共创 / 数字博物馆 / 公园 / 媒体研究 / 文创设计 / 产品开发 |

**5 个码位下藏着 54 个不同名称。** 这说明这些代码的语义是「族系」，
不是「这个标签的编号」。

**如果按代码建图会怎样**：「环太湖」和「文化创意」会变成同一个节点；
「GIS」和「数字化保护」会变成同一个节点。图谱直接失真，而且**看不出来**。

**处置**：
1. **照旧按「名称」建独立标签**（信息不丢——「环太湖」的 31 条不会消失）；
2. 把这些码位标记 `code_reliable=0`，界面/报告可据此提示「该码位不可作聚合依据」；
3. **自动检测，不硬编码**——码位表会随教师发布的新版词表变化，
   写死名单只能挡住眼前这几个。迁移时按 `(dim, code)` 统计 `COUNT(DISTINCT name)`，>1 即标记。

> 顺带说明为什么不塞进「未细分」桶：那样看起来"干净"，但会把 31 条「环太湖」的信息一并丢掉。
> **丢信息的"整齐"比不整齐更糟。**

### 3.3 图谱：L1 表派生，零抽取

课件把关系图谱划在「后续扩展」，本轮按用户决定做了**一个最小图谱页**——
但刻意不做实体抽取，全部关系由两张登记表 JOIN 得到：

- **节点 4 类**：`lit` 文献 / `img` 图像 / `tag` 标签 / `objtype` 图像对象类型
- **关系 5 类**：`contains` 文献→图像 / `depicts` 图像→对象 / `tagged` 文献→标签 /
  `imgtag` 图像→标签 / `cocite` 文献↔文献（共享标签）

**零抽取 = 零误判**。`cacx` 当年用规则抽机构，抽出了「大会主办」「结束二十国集团」这类碎片，
还因为 31.8% 的证据错挂返工过——本项目不碰那条路，所以不继承这些问题。

**三条口径纪律**（从 `cacx` 踩过的坑继承，写进了代码与验收）：

1. **筛选后的指标必须在筛选后的范围重算。** 分析与画图共用 `crop_scope()` 的输出。
   （`cacx` 曾出现「排名表跑全图、画的是子图」，中央网信办介数 0.194 → 0.8282，差 4.3 倍。）
2. **Louvain 必须锁 `seed=42`。** 验收脚本里有「两次调用结果一致」这条判据。
3. **连通块数不等于质量。** 界面同时显示「实际返回节点/边数」与「筛选后总节点/边数」，
   截断时标注「已截断」。**别把「图的样子」当成「现实的样子」。**

**点边出证据**（实测通过）：点 `lit:LIT-000175 → img:IMG-LIT-000175-001`，
右侧给出题名、图号「图1」、页码 4、图片路径、**图注全文**，以及「打开文献」跳转。

## 四、发出去：部署、访问、更新

### 4.1 启动

```
双击「启动.cmd」
```

脚本会：探测解释器（`py -3` / `python` / `python3` / 随包 `runtime\`）→
装依赖 → 首次自动迁移数据 → 起服务 → **自动打开浏览器**。
**关掉那个黑色命令行窗口 = 关服务。**

> ⚠️ 写 `.cmd` 的两条硬规矩（本轮都踩了）：
> ① **正文必须纯 ASCII + CRLF。** 中文写进 cmd 正文会被 cmd.exe 咬坏后续行 → 双击闪退。
> ② **文案里不能有裸括号。** `echo 02*(...)/04_xxx` 里的 `(` 会让 cmd 的复合语句块
> 解析崩掉（`/04_ was unexpected at this time.`）——**即使那个分支不执行，cmd 也要先解析**。
> 这两个坑都在真实窗口里跑出来后才发现，本机纪律「脚本类交付物必须在用户可见的真实窗口里验收」
> 正是为此。

### 4.2 访问范围

**默认只监听 `127.0.0.1`（仅本机）**——用户明确选择。
要让同学用手机打开（课件目标 04）：改 `config.json` 的 `app.host` 为 `0.0.0.0`，
用 `http://<局域网IP>:8771/` 访问。**只在可信内网做。**

### 4.3 更新

```powershell
python -m lzkg migrate     # 数据变了就重跑（幂等，17~22 秒）
# 重启服务即生效
```

### 4.4 离线可用

- 前端零 CDN（外链数实测 **0**）
- vis-network 运行时由后端从 pyvis 包内取出并内联（`/api/graph/vislib.js`）
- 「导出离线图谱 HTML」产出**自包含**文件，双击即开、断网可用（外链 0 处）

### 4.5 合规

- 使用条件以每条记录的 `开放类型/使用条件` 列为准（实测 14 种取值，
  其中「机构订阅获取｜CNKI」42 条、「付费（机构订阅下载）」8 条 **不得公开外传**）
- AI 初标只是候选标注，不是考古结论（页脚已注明）
- 图谱是「本数据集可观测到的关联结构」，不等于良渚文化的完整知识体系（页脚已注明）
- 复核覆盖率 19.6% 直接印在页面上，并注明「复核日期非空不代表已复核」

## 六、这套东西下一轮怎么用

1. **要更准的图**：拿到最新版词表后跑一次 `python -m lzkg migrate`，
   规范化规则会自动按新码位表重新检测「一码多义」。
2. **要更多文献**：新文献按同样格式登记进两张表 → 重跑迁移 → 站点自动多出内容。
   `cacx` 的通用采集器可以扩到新站点，`msyt` 的协作采集框架（成员端本机采集、回传合并）
   在需要多人分工时可直接移植。
3. **要做扩展项**：`app.py` 里图谱相关代码已按「表派生 / 抽取 / 模型旁路」三层留好接口，
   加抽取层不影响现有页面。
4. **并入主库**：`python -m lzkg export nbkg` 产出主库字段映射 CSV（含四维标签拆分与代码、
   来源三件套、开放类型），字段对照见 `_docs/数据契约.md` §4。
