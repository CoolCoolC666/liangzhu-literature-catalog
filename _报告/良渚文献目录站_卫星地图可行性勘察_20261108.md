# 良渚文化文献目录站 · 卫星地图可行性勘察

**勘察日期**：2026-11-08　**勘察人**：映月 Moonlgiht（AI 协作）
**结论一句话**：卫星影像**技术上完全可用**（已实测取到良渚真实卫星影像，0.5 m/像素级别清晰可见人工台地轮廓），本机可做**本地切片缓存**实现「零外链、断网可用」；但**许可与坐标真值是两道真门槛**——许可条款原文我没能取到可直接引用的版本，坐标真值目前只有 4 个点、18 个单遗址全空。

---

## 一、现状勘察（实测，不靠推断）

### 1.1 本站现在有两处地图，都是「纯矢量、零瓦片」

| 位置 | 代码位置 | 底图来源 | 交互 |
|---|---|---|---|
| 文献详情页小地图 | `index.html` 约 2011 行 `litmapDraw()` | 本地 `osm_qiantang_yuhang.geojson`（钱塘江水系 + 余杭区界）+ 良渚遗址群范围框矩形 | `scrollWheelZoom:false`，标记用 `L.divIcon` |
| 工作台「统计与地图」 | `index.html` 约 3409–3830 行 `MAPST` | 三档切换 `mapstTierFor(zoom)`：zoom<3 用 `world` / <7 用 `china` / 否则 `region` | 同源 `/basemap/<name>` 取 GeoJSON，8 色分类 |

- 全站 **`tileLayer` 调用数 = 0**（实测 grep）；**零外链**约束下没有瓦片服务，这两点是自洽的。
- Leaflet 1.9.4 已本地 vendor（`web/static/vendor/leaflet/`），由 `_tools/fetch_leaflet.py` 一次性下载 → **运行时零 CDN**，这条底线目前守得很好。
- 底图数据在 `data/basemap/`：9 个 GeoJSON（Natural Earth 公共域 8 个 + Overpass/OSM 1 个），合计约 23.4 MB，`manifest.json` 已记明来源与许可。
- 后端 `/basemap/{name}`（`app.py` 97–113 行）用正则 `^[A-Za-z0-9_\-.]+\.geojson$` 逐文件名校验防目录穿越——**新加瓦片路由必须照抄这个防穿越写法**。

### 1.2 坐标真值现状（这才是卫星图的真正瓶颈）

| 数据源 | 内容 | 能不能上图 |
|---|---|---|
| `data/遗址坐标.json` | **points 仅 4 条**：蜜蜂垄坝体剖面、MFL 高坝剖面点、良渚古城卫星影像中心、良渚古城遗址整体 | 能，且各带出处 |
| 同文件 `sites_without_coord` | **18 个单遗址全空**：莫角山、反山、瑶山、汇观山、钟家港、姜家山、官井头、卞家山、凤山、寺墩、福泉山、广富林、草鞋山、马桥、马家浜、崧泽、河姆渡、钱山漾 | **不能**（无坐标 ≠ 不画，缺坐标一律不画） |
| `data/coord_scan_v2.json` | 18 个遗址的 `per_site` **全为空数组**；命中的坐标全是**区域范围级**（如 `119°56′41″~120°03′28″`） | 范围框可画，单点不可 |
| `data/遗址点位表.xlsx`「区域代表点」 | 6 个分区为「是」（良渚古城/遗址群/全域/博物院/环太湖/姚江流域），精度两位小数 ≈ ±1.1 km | 能，但须标为「示意代表点」 |
| `data/lzkg.db` | **无坐标表**（坐标刻意不入主库） | — |

> 公开权威坐标交叉核验：良渚遗址 30°23′48″N / 119°59′07″E（30.39667, 119.98528）；遗址群范围东经 119°56′41″–120°03′28″、北纬 30°22′36″–30°26′17″（约 11.5 km × 7 km）；莫角山台地 670 m × 450 m、高 9–15 m、约 30 公顷。

**直接结论：卫星影像图做得再清楚，目前也只能标 4 个点 + 6 个区域代表点。** 18 个单遗址要能落在图上，必须先有 WGS84 坐标（人工抄录），这是绕不过去的前置工作。

## 二、卫星影像实测（真下载、真看图）

### 2.1 在线源可达性探测

| 服务 | 结果 | 备注 |
|---|---|---|
| **Esri World Imagery**（`server.arcgisonline.com/ArcGIS/rest/services/World_Imagery/MapServer/tile/{z}/{y}/{x}`） | **可达，匿名即可，无需 key**，HTTP 200 | 单张瓦片 19,574 B（z12） |
| Esri Reference（边界与地名） | 可达，HTTP 200，872 B | 与影像叠加用 |
| OSM 标准瓦片（`tile.openstreetmap.org`） | **超时**（20 s） | 本机网络下不可靠 |
| **天地图**（`t0.tianditu.gov.cn` WMTS） | **HTTP 418** → 拒绝匿名请求 | 须申请 key |

### 2.2 真实瓦片体量（实测平均单张字节，非估算）

| 层级 | 实测单张 | 良渚古城核心区 4 km×4 km 所需张数 | 该范围体积（按实测均值估） | 整个遗址群 11.5×7 km 体积 |
|---|---|---|---|---|
| z14（8.24 m/像素） | 17,387 B | 9 | ≈0.1 MB | ≈3.3 MB |
| z15（4.12 m/像素） | — | 25 | ≈0.3 MB | ≈10.9 MB |
| z16（2.06 m/像素） | 13,536 B | 72 | ≈1.0 MB | ≈41.6 MB |
| z17（1.03 m/像素） | — | 255 | ≈3.5 MB | ≈163.8 MB |
| z18（0.52 m/像素） | 8,820 B | 1,020 | ≈13.9 MB | ≈641.6 MB |

本机 E 盘空闲 **271.6 GB**，打包体量完全不构成障碍。

### 2.3 什么级别才看得见遗址本体（本次最关键的一条）

- **z15（4 m/像素）**：只看得出是良渚镇—苕溪一带的平原与城镇，**遗址完全淹没在农田里**。
- **z16（2 m/像素）**：仍是成片农田与厂房，**看不出古城轮廓**。
- **z18（0.52 m/像素）**：**清晰出现一组规则的人工夯土台地轮廓**——方形围合 + 数道平行夯土脊，与文献记载的「莫角山台地整體呈長方形覆斗狀、東西長 670 米、南北寬 450 米」形制吻合。

> 证据图（勘察A = z18 核心区、勘察B = z16 核心区、勘察C = z15 良渚镇一带）随**组内离线包**提供在同目录 `卫星地图勘察_图/`；
> **公开版不含这三张图**（影像许可未核实，不作公开再分发），本报告正文亦不含任何影像文件。
> ⚠️ 上面这段「吻合」是**形态学目视判断**，不是测绘结论；要把某段夯土认成莫角山/反山，必须靠坐标真值定位，而这正是 18 个遗址缺坐标的直接后果。

### 2.4 现成的开放许可替代：Sentinel-2

- AWS 公共桶 `sentinel-cogs` **免 key 可列出**（HTTP 200，XML 清单）→ 开放数据这条路技术上通。
- 但本机 **无 rasterio / 无 GDAL**（实测 `rasterio=False, osgeo=False`），只有 PIL + numpy → 要自己写 Sentinel-2 COG 的读取与重投影（EPSG:32650 → EPSG:3857），并出瓦片，是一笔实打实的工程量。
- 分辨率 10 m/像素 → **比 z18 差 20 倍**，上面那条「要看清遗址得 0.5 m」的结论会退回「看不清」。

## 三、三条落地路线

| | A. 本地切片缓存（Esri 影像） | B. 开放许可自建（Sentinel-2） | C. 在线直连（天地图 key） |
|---|---|---|---|
| 零外链 | ✅ 同源 `/tiles/{z}/{x}/{y}.jpg` | ✅ 同源 | ❌ **直接破坏零外链** |
| 断网可用 | ✅ | ✅ | ❌ |
| 影像清晰度 | **0.52 m/像素（可看清台地）** | 10 m/像素（看不清） | 依源而定 |
| 打包体积 | 核心区 z14–z18 ≈ 18 MB | 视重采样方式 | 0 |
| 工程量 | 小：1 个后端路由 + 前端加底图层 + 下载脚本 | 大：需装 rasterio/GDAL 并写重投影与出瓦片 | 最小，但破坏底线 |
| 许可 | ⚠️ **未取到条款原文**（见下） | ✅ 开放数据，署名即可 | ⚠️ 需 key + 审图号 + 署名 |
| 能否进公开 GitHub | ❌ 不建议进 | ✅ 可以 | ❌ 破零外链 |

### 许可这一栏要说清楚（已核实 / 未核实分开写）

**已核实：**
- 天地图：注册 → 申请「个人开发者」→ 创建应用（选「浏览器端」）即可拿 key，免费额度 1 万次/天；裸请求返回 418 说明服务端确实在拦匿名访问。
- 天地图 / 各类中国互联网地图服务：**引用必须注明地图来源与审图号**；现行要求来自自然资源部办公厅、工信部办公厅〔2024〕972 号文（APP 登载使用地图规范），要求准确反映中国领土范围、行政区划、重要岛屿并标示审图号。

**2026-11-08 补充（已核实）：**
- Esri 官方《数据归属和使用条款》（<https://www.esri.com/zh-cn/legal/terms/data-attributions>）原文：
  「以下条款补充和修订 Esri 对其提供的以下识别数据的使用许可条款」；其中对「非商业用途或内部用途
  + 可再分发硬拷贝或软拷贝图像，供个人或内部使用」给出了明确口径（Environics Data 条）。
  → 我方用途（课程作业 + 组内离线分发）落在「个人/内部使用」这一侧，**组内离线包带瓦片 + 保留完整署名**。
- **署名行取自服务自身**：World Imagery MapServer 的 `copyrightText` 原文为
  `Source: Esri, Vantor, Earthstar Geographics, and the GIS User Community`（Vantor 即原 Maxar）。
  页面角标与清单 manifest 都用这一行，不自己编。

**仍未核实（不要当结论用）：**
- World Imagery 自身在 Esri **主协议（Master Agreement）** 下的再分发条款原文**仍未取到**
  （条款页抓取 404 / 动态渲染）。所以**公开仓库与公开 Release 暂不带瓦片**（保守处理，
  打包脚本里已加硬断言拦着）。OSM Wiki 上「Esri 允许在 OSM 中使用 World Imagery、无需署名」那句，
  语境是**引用该服务**，不等于允许把瓦片**打包再分发**。

**由此得出的稳妥边界（建议按此执行）：**
- 卫星瓦片**只放组内离线对接包**，**不进公开 GitHub 仓库、不挂公开 Release**；
- 公开版仍只有 Natural Earth 公共域矢量底图（现状不动）；
- 页面保留**署名位**（如「影像：Esri World Imagery」），把署名问题降级成「已标注」而不是「未授权」；
- **只做良渚核心区局部**，不铺中国全域卫星图 —— 局部图不涉及国界/省界/岛屿绘制，**不触发「问题地图」与审图号那条红线**；若哪天要做全域卫星图，这条就得重新走审图号流程。

## 四、落地要动的代码（已定位到行）

1. **后端** `lzkg/app.py`：新增 `/tiles/{z}/{x}/{y}.jpg` 路由，**照抄 `/basemap/{name}` 的防目录穿越写法**（白名单正则 + 只放行 basemap 目录）；瓦片目录 `data/basemap_tiles/{z}/{x}/{y}.jpg`。
2. **前端** `lzkg/web/static/index.html`：
   - 详情小地图（2030 行 `L.map`）与工作台地图（3809 行 `L.map`）各加一层 `L.tileLayer('/tiles/{z}/{x}/{y}.jpg', …)` 与「矢量 / 卫星」切换；
   - 保留矢量层的既有合规逻辑：**绝不画 admin_0 里 CHN 那个国界多边形、台湾与大陆同色同边线不单独标注、`on_map=false` 与 lat/lon 为 null 的一律不画点**。
3. **判据**：`tests/test_all.py` 552 行的「零外链」判据只查 `src/href` 是否指向 http(s) → **同源 tileLayer 不会触发它**，但建议**新增一条**：卫星底图 URL 必须同源、且必须存在本地瓦片目录清单。
4. **下载脚本**：新增 `_tools/fetch_tiles.py`（一次性下载 + 断点续跑 + 落 manifest 记录来源与时相）。
5. **打包**：`03-对接包` 体积从 1.9 GB 增至约 1.92 GB（核心区 18 MB）；公开版打包脚本需排除瓦片目录。

## 六、建议（供拍板）

按「先出单页样例版再推广」的老规矩，我建议 **A 路线 + 只做良渚古城核心区（4 km×4 km，z14–z18，约 18 MB）**，先只在**文献详情页那张小地图**上加「矢量 / 卫星」切换，看到效果再决定是否推广到工作台统计地图、是否扩到整个遗址群。坐标真值（18 个单遗址）可以同步启动人工抄录——不必等它，卫星图可以先只标已有的 4 个点。
