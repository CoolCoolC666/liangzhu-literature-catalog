## 〇、先把三个问题说清楚（诊断，不含方案）

### 问题 1 · 详情与总览重复

**根因不是内容重复，是「详情」被错放成了顶层页签。**

详情页本质是**下钻页**——它必须从某条记录进入、带着「← 返回」的上下文。
现在导航栏把 `总览 / 浏览 / 检索 / 详情 / 图谱` 并列成 5 个平级入口，
用户点「详情」进去看到的是 `当前文献编号：LIT-000002`（一个默认值），
和从列表点进来的效果一样，但**失去了来路**——所以它看起来像「总览的翻版」。

真正的内容重复有 3 处：

| 重复点 | 总览里的 | 详情页里的 | 该怎么分工 |
|---|---|---|---|
| 图版 | 「图版速览」12 张缩略图 | 「图版（4 张）」带图注+页码 | 总览只放**计数与入口**，不放缩略图墙 |
| 标签 | 「时间分期标签分布」等 4 张分布条 | 「四维标签」原文 | 总览放**分布**，详情放**这一条的** |
| 规模数 | 6 个大数字卡 | 「文献总数/图版数/复核率」3 个小卡 | 详情页的规模卡是**全局数**，与本条无关 → 删 |

**结论**：导航去掉「详情」；总览收敛成「统计 + 入口」；详情只作为下钻页存在。

### 问题 2 · 浏览与检索功能重复，建议合并

**这个建议是对的，而且有两个独立证据支持。**

**证据 A（同一门课的姊妹工程）**：msyt 的页签是
`总览 / 检索与浏览 / 采集与协作 / 完整性体检 / 采集日志`——
**「检索与浏览」本来就是合并的**。

**证据 B（cacx）**：它的 7 个页签是
`检索 / 数据面板 / 样本配置器 / 关系图谱 / 设置 / AI 摘要 / 数据同步`——
**根本没有独立的「浏览」页**。检索页自己就带栏目、年份、日期区间筛选，
浏览需求被检索页吃掉了。

**本项目为什么显得重复**：我把「浏览」做成「带分类下拉、不带关键词框的列表」，
把「检索」做成「带关键词框的列表」——**同一份列表渲染了两遍**，
只是顶部控件不同。功能上并无二致。

**合并后的形态**（一个页签，控件是并集）：

```
┌─ 文献 ────────────────────────────────────────────────┐
│ [关键词______] [类型▾][语种▾][年份▾][分期▾][空间▾][主题▾] │
│                              [重置] [⬇导出当前结果 CSV] │
├──────────────────────────────────────────────────────────┤
│ 命中 67 条 / 返回 20 条    复核覆盖率 19.6%（按状态字段统计） │
│ ① 良渚古城…   2018  DOC-AR｜学术论文  zh｜中文  [标签…]   │
└──────────────────────────────────────────────────────────┘
```

- 关键词**留空** = 浏览（按类别翻，一屏扫完）
- 关键词**填了** = 检索（关键词 AND 类别，两条件同时生效）

**这同时把课件第 13 页的 01/02 两项一次做对**，且不新增功能。

### 问题 3 · 知识图谱无法固定

这个要拆成**三层**，「无法固定」在三层上表现完全不同：

| 层 | 现象 | 根因 | 现状（我这边 / cacx 那边） |
|---|---|---|---|
| **a. 布局层** | 每次打开，节点位置都不一样 | vis-network 的物理布局**初始位置随机**，收敛结果自然每次不同 | **我这边：没处理。cacx 那边：也没处理**——它只做了「视野自适应」（等 `stabilizationIterationsDone` 再 `fit`），**布局本身照样每次变**。所以**不能指望抄 cacx** |
| **b. 交互层** | 拖动节点后位置丢失；没有「复位」 | 布局是纯前端算的，没有持久化 | 我这边：没做 |
| **c. 口径层** | 说不清「现在这张图到底是什么」 | 我只给了 2 个口径（实际返回 / 筛选后总数） | **cacx 给了 3 个**：分析口径（min_degree=2）12162 节点 / 29069 边 / 886 连通块；画布默认 300 节点 / 2995 边；聚焦某机构 1 跳 815 节点 / 4288 边。它的《使用前必看》专门警告「数字有三个口径，别混着念，念错当场被问住」 |

**还有一条我这边更严重的**（cacx 用另一种方式绕过了）：

> cacx 实测：画布容器 798×620 CSS 像素，自动铺满后 **缩放比 ≈ 0.27**；
> 节点间距约 **19 像素**，标签实际字号 **2–3 像素**。
> 结论：「默认视图下在图上瞄准并点中一条指定边几乎不可能成功」。

我这边更糟：默认画 600 节点 / 7 140 边，**密度是它的 2 倍**。
→ **光修布局不够，还得把「点边」从画布上挪走**（cacx 的解法：画布 + 边列表双通道，
演示只走边列表）。

### F2 · 图谱固定（三件套 + 一条兜底）

#### ① 确定性布局（解决「每次打开位置都不同」）

**方案**：布局在**后端算**，用 networkx 的确定性算法，前端只画不模拟。

| 项 | 做法 |
|---|---|
| 算法 | `nx.spring_layout(G, seed=42, k=..., iterations=...)`；节点过多时换 `nx.kamada_kawai_layout` 或 `nx.fruchterman_reingold_layout(seed=42)` |
| 坐标存哪 | `graph_nodes` 加两列 `x REAL, y REAL`；`migrate` / `rebuild-graph` 时算好写入 |
| 前端 | `physics: false`（**关掉物理引擎**）+ 节点带 `x/y`；用 `fixed: true` 防止拖动漂移 |
| 尺寸归一 | 算完把坐标缩放到 `[-1, 1]`，前端按画布尺寸线性映射 → 与画布大小无关 |

**为什么不抄 cacx**：cacx 用的还是前端物理布局，它只做了「等稳定后再 fit」，
**布局本身每次都变**（它的演示脚本里也承认「位置可能略有不同」）。
→ **这一条要自己写，比抄更值钱。**

**代价**：后端算布局的时间。3000 节点 spring_layout 大约 **1–3 秒**，
可以接受；超过 1 万节点要改用子图采样 + 预计算。

#### ② 坐标持久化 + 用户微调可存

| 能力 | 做法 |
|---|---|
| 拖动后保存 | 拖动结束（`dragEnd`）POST 节点新坐标 → 写 `graph_nodes.x/y`（带 `layout_version` 标记） |
| 「固定 / 自由」开关 | 固定 = 用存下来的坐标；自由 = 交回物理引擎 |
| 「复位布局」按钮 | 清掉人工坐标，回到自动算的版本 |
| 何时重算 | 换筛选条件时，如果子图变了就重算（子图内相对位置尽量保持：可把旧坐标投影到新子图上） |

**一个务实的取舍**：第一版可以**不做拖动保存**（只做「固定 + 复位」），
因为拖动保存会带来「不同人打开看到的图不一样」的新问题。**先固定，别急着个性化。**

#### ③ 口径三件套（解决「说不清这张图是什么」）

现在只有 2 个口径，按 cacx 的教训要补成 3 个：

| 口径 | 含义 | 本项目当前值 |
|---|---|---|
| **① 筛选后总量** | 当前筛选条件下图谱**本来有多少** | 3 491 节点 / 31 876 边（min_degree=1） |
| **② 画布实际绘制** | 因为 limit 截断，**实际画出来多少** | 600 节点 / 7 140 边（limit=600） |
| **③ 聚焦子图** | 聚焦某节点 N 跳后的规模 | 聚焦 `lit:LIT-000175` 1 跳 = ? 跳 |

**界面必须同时显示这三个**，并写一句：
「念数字前先看口径区；口径变了就得重测」——
这是 cacx《使用前必看》和演示脚本都强调的。

**顺带**：`min_degree` 滑块要显示「改这个数字，图会变成什么样」的即时预览（节点/边数实时变），
否则用户调完不知道效果。

#### ④ 兜底：把「点边」从画布挪到列表（解决「点不中」）

cacx 的实测结论直接适用：**画布缩到 0.27 时边只有 19px、标签 2–3 像素，点不中**。
我这边 600 节点 / 7 140 边，密度是它 2 倍，更点不中。

**做法**（照 cacx）：画布**左边**、**边列表右边**，两者联动：
- 边列表可排序（按关系类型 / 按证据条数 / 按文献号）、可搜索
- 点列表某一行 → 画布**聚焦**到那对节点（其余淡出）→ 右侧出证据
- 画布点边 → 列表对应行高亮滚动
- **「演示只走边列表」**——这条要写进演示脚本

**边列表的数据来源**：`/api/graph` 现在只返回前 limit 个节点及其边。
需要补一个 `/api/graph/edges` —— 返回**筛选后的全部边**（可分页、可搜索），
不截断节点。边数 3 万条，SQLite 查没问题。

#### ⑤ 后台计算（防止大图卡死）

我现在的 `/api/graph/analysis` 是**同步算**的（networkx 介数中心性在请求里阻塞）。
cacx 的实测：全库介数中心性要 **460 秒**，它因此改成后台任务 +
页面显示「正在计算：介数中心性 · 已等待 N 秒」+ **同一时刻只允许一个计算**。

**建议照抄**：
- 算力重的指标（介数中心性、Louvain 社区）放后台任务
- 页面轮询进度（`/api/graph/analysis/status`）
- **单任务锁**：已在算就返回「另一个计算正在进行中」
- **先给度数**（秒级），介数与社区稍后补上——别让用户等

**工作量**

| 子项 | 后端 | 前端 | 小计 |
|---|---|---|---|
| ① 确定性布局 | 1.5h（layout 计算 + 存 x/y + 归一） | 30min（physics:false + 用 x/y） | 2h |
| ② 固定/复位（不含拖动保存） | 20min | 30min | 50min |
| ③ 口径三件套 | 40min | 40min | 1.3h |
| ④ 边列表 + 联动 | 40min（新端点） | 1.5h | 2.3h |
| ⑤ 后台计算 | 2h（任务队列 + 状态 + 锁） | 1h（轮询 + 进度条） | 3h |
| **合计** | | | **≈ 1.5 人日** |

**验收**（照 cacx R2 的验收标准写法）
1. 同一筛选条件下**连续打开 3 次图谱，节点位置完全一致**（截图比对）
2. 改 `min_degree` 后再改回来，布局回到原样
3. 边列表能搜到某条边（如 `LIT-000175`），点它 → 画布聚焦 + 右侧出证据（题名/图注/页码）+「打开文献」可达
4. 口径区三个数字都在，且与「筛选后总量」页签的独立统计一致
5. 焦点在 3 491 节点时点「分析指标」，**页面不卡死**（其他页签照常用），显示进度

### F3 · 文献导入与导出（以根目录那两份表为模板）

#### 先说清那两份「模板」到底是什么（实测，不是猜的）

| 文件 | 结构 | 内容状态 |
|---|---|---|
| `02(良渚文化)(…)/文献基本信息登记表.xlsx` | 204 行 × **32 列** | **空白模板**——只有表头 + 200 行空行；只有第 5 行有 3 个零散值（序号 1 / 主题「良渚」/ 题名「《早期中华文明的整体性与区域性》」） |
| `02(良渚文化)(…)/文献图像信息登记表.xlsx` | 204 行 × **26 列** | **空白模板**——200 行几乎全空（只有序号） |

**它们是「给人填的空白登记表」，不是数据表。** 而它们的**表结构规范**是固定的：

```
行1  标题          「宁波地域文明探源工程（二期）文献基本信息登记表」
行2  填写说明      「带*字段必填；标签填写受控词表代码及名称，可多值并列（用；分隔）…」
行3  （空行）
行4  表头          32 列 / 26 列
行5+ 数据
```

**与 `05_登记表/00-最终版` 的关系（实测）**：
- 文献表：列名与顺序**完全一致**，最终版只多 2 列 → `数据来源类型*`、`来源判据（痕迹）`（两列在最终版 200/200 全填满）
- 图像表：列名与顺序**完全一致**（26 列），最终版把 200 个空行换成了真实的 **3 162 行**

> **所以「导入导出」= 让这个空白模板成为双向的接口**：
> **导入** = 别人填好这张表 → 灌进网站；**导出** = 网站里的数据 → 导成这张表的格式 → 交出去/存档。
> 而且它天然把**组内协作**和**并入主库**串起来了（见 §3.3 末尾的闭环）。

#### 设计要点 1 · 按「列名」匹配，不按「列号」

32 列模板与 34 列最终版**列名顺序一致**，所以按列名匹配可以同时吃两种：

| 情况 | 处理 |
|---|---|
| 模板 32 列 | 正常导入；**提示**「本表缺 `数据来源类型*`、`来源判据（痕迹）` 两列，将留空」 |
| 最终版 34 列 | 正常导入，两列一起进 |
| 列名带 `*` | **`*` 是必填标记，不是列名的一部分** → 比对前统一去掉尾部 `*` |
| 列名不认识 | 忽略并列出（不阻断导入） |
| 关键列缺失（如没有「文献标识符」） | **直接拒绝**，报清楚缺哪列 |

#### 设计要点 2 · 表头定位不能写死「第 4 行」

规则：**扫描前 12 行，找含「文献标识符」或「图像标识符」（去 `*` 后）的那一行**作为表头；
数据行 = 表头行之后所有非空行。标题行、填写说明行**不算数据**（否则会被当成一行脏数据导入）。

> ⚠ **这也是要顺手修的既有隐患**：现在 `migrate.py` 的 `_read_sheet()` 用「非空单元格数 > 5」定位表头。
> 迁移时够用（表结构我们自己控制），但**导入器必须改成按关键列名定位**——
> 万一对方在「填写说明」行里写了一大段分列说明，就会整表错位。
> **同一个函数两套用途，要拆开。**

#### 设计要点 3 · 导入必须是「预检 → 人工确认 → 入库」三步

**预检报告（dry-run）**必须给出四类计数 + 三张清单：

| 分类 | 判定 | 默认动作 |
|---|---|---|
| **新增** N | 标识符在库里不存在 | 插入 |
| **更新** N | 标识符已存在、且内容有变化 | **逐条列出「原值 → 新值」**，人工确认 |
| **跳过** N | 标识符已存在、内容完全相同 | 跳过 |
| **冲突** N | 标识符相同但**关键字段**不同（如同一 LIT 的题名/类型变了） | **默认不覆盖**，逐条人工裁决 |

外加：
- **缺必填**清单：`*` 标记字段为空的行 → **拦在库外**，报告列出行号与缺哪几列
- **缺列**提示：表里没有的列（32 列模板缺 2 列）→ 说明这 2 列将留空
- **图像表专属**：逐行检查 `图像相对路径` 指向的文件**在磁盘上是否存在**，输出两张清单
  - 「登记表有但磁盘没有」（→ 这些行**不能进正式表**，否则详情页空图、图谱的 `contains` 边指向不存在的图）
  - 「磁盘有但登记表没有」（→ 潜在漏登记）

#### 设计要点 4 · 幂等 + 不覆盖 + 可回滚

| 要求 | 做法 |
|---|---|
| **幂等** | upsert 主键 = `文献标识符` / `图像标识符`；同一份文件导两次，第二次应全部「跳过」，库零变化 |
| **不误伤** | 冲突项默认不覆盖；更新项先列差异再落库 |
| **可回滚** | 导入前用 SQLite backup API 把库快照到 `data/backups/lzkg-<时间戳>.db`（几秒） |
| **留痕** | 新增 `import_log` 表：时间、文件名、来源、增/改/跳/冲突数、必填缺失数、操作人 |

#### 设计要点 5 · 三条导入通道

| 通道 | 命令 | 用途 |
|---|---|---|
| **CLI** | `python -m lzkg import <xlsx> --kind lit\|img [--dry-run\|--commit]` | 批量、大数据、脚本化 |
| **Web 上传** | 页面「导入」按钮 → 选文件 → 看预检报告 → 确认 | 组内成员零门槛用 |
| **拖拽** | 把 xlsx 直接拖到列表页 → 自动预检 | 顺手 |

Web 导入要**限量**（单文件 ≤ 20 MB / ≤ 5 000 行），超了提示走 CLI。

#### 设计要点 6 · 导出要出 6 种形态

| # | 形态 | 格式 | 用途 |
|---|---|---|---|
| ① | **模板版**（文献 32 列 / 图像 26 列） | xlsx | **与根目录那两份完全同构**（行1 标题 / 行2 说明 / 行3 空 / 行4 表头 / 行5+ 数据）。**别人拿到就能直接填** |
| ② | **完整版**（34 列） | xlsx | 多 `数据来源类型` `来源判据（痕迹）`，**信息最全**，主库对接用 |
| ③ | 精简版（≈10 列必填） | xlsx | 给不需要全字段的人 |
| ④ | 当前筛选结果 | xlsx + CSV | 列表页「⬇导出当前结果」（CSV 已有） |
| ⑤ | 机器可读 | JSONL / CSV | 程序对接 |
| ⑥ | 主库字段映射 | CSV | 已有 `export nbkg` |

**导出三条硬要求**：
1. **主格式必须是 xlsx，不能只给 CSV** —— CSV 会丢「填写说明」行和表头样式，**别人拿到没法直接填**。
2. **必须带口径页脚**：导出时间、筛选条件、条数、数据版本（CSV 已有，xlsx 放第二个 sheet「导出说明」）。
3. **round-trip**：导出的文件能**原样导回去**（这是验收硬判据，不是锦上添花）。

#### 这条链顺带把协作和并库串起来了

```
组员拿 ① 模板版导出 → 本地填自己那部分 → 交回 xlsx
      → 审核方 import --dry-run 看冲突 → 逐条裁决 → --commit
      → 导出 ② 完整版 → 并入 nbkg 主库
```

**这就是 msyt 说的「CSV 是唯一交接口」的同构做法**——只不过我们交的是 xlsx（保格式）。

#### 工作量

| 子项 | 后端 | 前端 | 小计 |

| 表头定位 + 列名映射（含去 `*`） | 1.5h | — | 1.5h |
| 预检（增/改/跳/冲突/缺必填/缺列） | 2.5h | — | 2.5h |

### F4 · 站点的「xlsx 模板下载 / 导出」

**核心判断**：模板**不能是「下载一个附件」**，必须**由代码生成**——
否则导入器和模板会各自漂移（今天就实测到「32 列模板 vs 34 列最终版」这类问题）。

**★ 单一事实来源（这一条是 F4 的全部意义）**

现在列定义散在**三个地方**：
`migrate.py` 的 `LIT_COLS`/`IMG_COLS` → `make_templates.py` 的 `LIT_DICT`/`IMG_DICT`
→ **根目录那两份 xlsx 本身**。
**改一处忘另两处 = 模板和导入器对不上。**

收口成一个文件：

```
lzkg/schema/registry_columns.json        ← 列定义的唯一来源
   {
     "literatures": {
       "sheet": "文献基本信息",
       "title": "宁波地域文明探源工程（二期）文献基本信息登记表",
       "note":  "填写说明：带*字段必填；标签填写受控词表代码及名称，可多值并列（用；分隔）…",
       "columns": [
         {"no":1,  "name":"序号",         "required":false,"width":8,  "example":"1"},
         {"no":2,  "name":"文献标识符*",   "required":true, "width":18, "example":"LIT-000001"},
         {"no":22, "name":"开放类型/使用条件","required":false,"width":24,"example":"开放获取(OA)"},
         {"no":33, "name":"数据来源类型*", "required":true, "width":22,"example":"S1｜中国知网(CNKI)",
          "in_template32": false,
          "note":"最终版新增列；32列模板缺此列时留空"}
       ]
     },
     "images": { ... }
   }
```

然后**四件事共用它**：

| 谁 | 读什么 |
|---|---|
| 站点「下载空白模板」按钮 | 生成 xlsx |
| `make_templates.py` | 生成 `_docs/字段模板/*.xlsx` |
| 导入器 | 列名映射 + 必填校验 + 缺列提示 |
| 根目录那两份 xlsx | **由它生成**（或至少逐列比对验证一致） |

→ **「模板下载」「模板导出」「导入校验」永不漂移。**

**站点上的四个按钮**

| 按钮 | 位置 | 产出 |
|---|---|---|
| ⬇ **下载空白模板（文献）** | 文献页 / 导入面板 | 32 列 xlsx：行1 标题 / 行2 填写说明 / 行3 空 / 行4 表头 |
| ⬇ **下载空白模板（图像）** | 同上 | 26 列 xlsx |
| ⬇ 导出当前结果 | 文献页 | xlsx + CSV（CSV 已有） |
| ⬇ 导出模板版 / 完整版 | 导出面板 | F3 的 6 种形态 |

**两条硬要求**：
1. **模板必须带「填写说明」行**（就是根目录那两份的第 2 行原文）——
   **交付给别人时，表格本身要能自我解释**，不能靠口头交代。
2. **下载的模板要与根目录那两份一致** → 用同一份 `registry_columns.json` 重新生成后，
   与 `02(良渚文化)(…)/文献基本信息登记表.xlsx` 做**逐列比对（列名 + 顺序）**，
   **必须 0 差异**才算通过（这是 F3-7 的加强版）。

**为什么这条值得单独做**：组内协作、跨组交换、主库并入，**全都要靠这张表**。
它就是本项目的**对外数据契约**。

## 四、公网发布方案（域名 + Cloudflare）与开源工具选型

### 4.1 现状：本机已具备的条件（实测）

| 条件 | 状态 | 证据 |
|---|---|---|
| `cloudflared` | ✅ **已装** | `C:\Users\you\AppData\Local\Programs\cloudflared.exe` |
| Java 26 | ✅ **已装** | OpenRefine 可直接跑 |
| `defusedxml` | ✅ 0.7.1 | 解析上传 xlsx 内部 XML 时防 XXE / billion laughs |
| `lxml` / `openpyxl` / `jwt` / `httpx` | ✅ 已装 | — |
| 隧道 + 启停脚本范式 | ✅ **现成** | msyt 的 `web.ps1 start -Tunnel` + `tunnel-domain.txt` + `cloudflared-tunnel.token` |
| `msyt/auth.py` | ✅ **现成可移植** | 密码哈希 **scrypt**（标准库，零依赖，比 PBKDF2 强）+ members 白名单 + 邮箱域策略 |
| 域名 | ⬜ **你填** | `tunnel-domain.txt` 一行一个域名 |

**直接抄 msyt 的三步**（已实测过的那套）：

```powershell
cloudflared tunnel create lzkg-local      # 令牌存 data/cloudflared-tunnel.token
# data/tunnel-domain.txt 填域名（一行）      # 启停脚本自动读，换域名不用改脚本
.\web.ps1 start -Tunnel
```

**三个坑（msyt 踩过的，直接抄）**：
- 域名用**同级子域**（`lzkg.example.com`）——**两级子域**（`api.lzkg.example.com`）证书可能一直签不下来
- 隧道日志报 `failed to dial to edge with quic: timeout` → 本机 UDP 不通 →
  在 `tunnel-protocol.txt` 写 `http2` 走 TCP，通常立刻通
- 公网访问被弹到 `cloudflareaccess.com/.../login` → **那是 Access 门在起作用，不是故障**

### 4.2 暴露到公网前的八条硬规矩（按「仅成员内部开放」重新定）

> ★ **2026-10-28 用户明确**：公网**仅成员内部开放**，用于组内协作与调试，
> **资料展示与下载无需过严**。
> → 这条把风险方向整个换了个：**不是「版权泄露」，而是「搜索引擎收录」**。

**★ OpenRefine 怎么用（这就是「参考开源 XML 工具」的最优解）**

我们的最大数据痛点是**一码多义的标签**（`S-0802` 下 18 个名称、`S-0801` 下 11 个、`R-0199` 下 8 个）。
OpenRefine 正是干这个的，而且**本地跑、数据不出机、有中文界面**：

```
① 用本站「导出当前结果」导出 文献基本信息.xlsx
② 丢进 OpenRefine（本地小服务器，不联网也能用）
③ 用 GREL 表达式把标签列拆成「代码 / 名称 / 限定」三列；
   用聚类把「同码不同名」挑出来，人工确认归并
④ 导出 xlsx → 回本站导入（走 F3 的「预检 → 确认」通道）
```

**它的定位必须说清**：
- ✅ **离线清洗工具**（人来用），**不是网站运行时的一部分**
- ✅ **不能成为启动依赖**（Java + 一个大 jar，交付包会变重）
- ✅ 但它是**我们数据质量最缺的那块**的最佳解法
- 备选：`csvkit` 或 Python 脚本也能拆分，但**没有可视化聚类和人工确认界面**

**★ xlsx 上传的两个安全点**（xlsx 本质是 zip + XML）：

| 风险 | 处置 |
|---|---|
| **zip 炸弹**（解压比超限） | 限制**解压后总大小**与条目数——**只限压缩包大小是不够的** |
| **路径穿越**（zip 内条目名含 `../` 或绝对路径） | 拒绝 |
| **XXE / billion laughs**（内嵌 XML） | 用 `defusedxml` 解析内部 XML（openpyxl 对 zip 路径有基本防护，但上限要自己设） |

| 高德 JS API | 个人 key 有日配额；**商用授权另计（公开报价 5 万起）** | GCJ02 | 教学/非商用一般可用，但受配额与条款约束 |
| 百度地图 JS API | 同上 | BD09（**二次加密**） | 同上 |
| OSM + 瓦片 | 免费但要自找瓦片源 | WGS84 | 内网/离线可用；**国内访问慢、瓦片版权要查清** |

#### ④ 四个必踩的坑

| # | 坑 | 说明 |
|---|---|---|
| 1 | ★ **API key 不能硬编码在前端** | 百度/高德都要求用**「域名白名单」**限制 key 的可用来源，否则 key 会被盗刷 |
| 2 | ★ **署名不能省** | 各家都要求在页面标注服务方名称 |
| 3 | ★ **配额** | 个人 key 日调用量有限；站点被收录或被人刷都会触发 |
| 4 | ★ **别用「拾取坐标」当原始坐标** | 从高德页面拾取的是 GCJ02、从百度拾取的是 BD09、卫星影像上是 WGS84 —— **来源决定坐标系** |

#### ⑤ 落到本项目

| 项 | 做法 |
|---|---|
| 点位表 | `data/遗址点位表.xlsx`（组内查证坐标）→ 列：名称 / WGS84 经纬 / 所属区域 / 出处 / 备注；**同样由 `registry_columns.json` 式的方式管理** |
| 三套坐标 | 迁移时算好三套入库，前端按底图选列 |
| 前端 | 点标记 → 弹出该点涉及的文献（复用文献页列表组件） |
| 诚实边界 | ① 坐标是**组内补充**，不是原始数据来源 → 界面要写明<br>② 空间分区标签是**文献讨论范围**，不等于「发掘就在这个点」——地图只能表达「**哪些文献谈到过这里**」 |
| 离线兜底 | 底图 API 不可用时（内网无外网）→ 退化为**纯列表 + 示意图**，**不白屏** |

### 草稿 1 · 登录与个人收藏

**设计目标**：单机形态下提供「个人化」，同时**把账号体系的地基一次打牢**，将来真开网不返工。

**三档形态**

| 档 | 形态 | 账号 | 收藏归属 | 工作量 | 建议 |
|---|---|---|---|---|---|
| 1 | 纯本机档案 | 无 | 全局一张表 | 0.5h | |
| 2 | **本地多用户** | 轻量本地账号（用户名 + 密码哈希 + 角色） | 按 `user_id` | 1.5 天 | **★ 建议做这档** |
| 3 | 开放注册 + 审核 | 第 2 档 + `pending/active` 状态机 + 管理员审核页 | 按 `user_id` | 3 天 | 等真要开网再说 |

**第 2 档的具体设计**

| 项 | 做法 | 纪律 |
|---|---|---|
| `users` 表 | `id, username, pass_hash, salt, role, status, created_at` | 密码**只存哈希** |
| 密码哈希 | ★ **scrypt**（`hashlib.scrypt`，标准库、**零新增依赖**、内存硬函数，比 PBKDF2 更强）——**直接移植 msyt 的 `auth.py`** | 不用明文、不用 MD5/SHA1 |
| 会话 | 两种都行：**msyt 用的是 JWT**（PyJWT 已装，密钥存 `meta` 表，TTL 到期）；状态化 token 则是另一条路 | 本项目**建议直接抄 msyt**：代码已实测过，且 PyJWT 本机已装 |
| `favorites` 表 | `(user_id, lit_id, created_at, note)`，主键 `(user_id, lit_id)` | 一人一文献一条 |
| 角色 | `admin` / `member` 两个就够（抄 msyt） | 不搞 RBAC |
| 登录白名单 | ★ **members 表**（只有 `status='active'` 的邮箱能登录），可加「只允许某个邮箱域」策略 | 抄 msyt：**组员可能用同一个学校/团队邮箱** |
| 建号方式 | **只允许本机创建**（首个建号为 admin） | 开放注册 = 第 3 档的事 |
| 移植成本 | ★ **几乎为零**——msyt 的 `auth.py` 已含 scrypt + JWT + members 白名单 + 两道权限 | 直接抄，别重写 |

**权限两道**（抄 msyt）：
- **界面层**：未登录不显示「我的收藏」页签（不是灰掉，是**不出现**）
- **接口层**：收藏相关端点一律 `require_user`，手动构造请求也得 401/403
- **缺一道等于没锁**：只藏界面 → 改 URL 就能调

**界面**

- 导航新增「我的收藏」（**仅登录后出现**）
- 文献详情页右上角「☆ 收藏 / ★ 已收藏」
- 收藏页 = 文献页**同款列表组件**（不要重写一套）
- 登录页：用户名 + 密码；登录后能改密码

**验收**

| 编号 | 标准 |
|---|---|
| L1-1 | 未登录点「☆ 收藏」→ 跳登录页，**不静默失败** |
| L1-2 | 收藏后**刷新页面仍在**（持久化，不是内存） |
| L1-3 | 换另一个账号登录，**看不到上一个人的收藏** |
| L1-4 | 直接构造请求调收藏端点 → 401/403 |
| L1-5 | 查数据库**搜不到任何明文密码** |
| L1-6 | 未登录时接口 `/api/users/me` 返回 401，且**不泄露**用户列表 |

### 草稿 2 · 在线录入与共同编辑

#### ★ 核心决定：**不做实时协同**

**理由**：CRDT / OT 的成本与本项目规模（200 篇、几个组员）严重不匹配。
而且课件写的是「需要权限与同步」——**提案—审核制同样满足「同步」**，
并且**更贴合任务书的要求**（「每条记录必须保留责任人和审核人」）。

msyt 的协作采集就是这个范式：**成员端采集 → 回传 → 并入权威库，走同一套完整性判据**。

#### 设计成三段

```
① 录入者填表（在线表单 / 或导入 xlsx —— 走 F3 那条通道）
        ↓
② 存 staging（带 proposer、状态 pending、**逐字段差异快照**）
        ↓
③ 审核人在「待审」页逐条看左右对比 → 采纳 / 驳回 / 退回修改
        ↓
   采纳 → 写正式表 + 写 import_log + 重算标签与图谱
```

| 项 | 设计 | 纪律 |
|---|---|---|
| 录入通道 | 在线表单（必填项按 32 列模板排布）+ F3 的 xlsx 导入 | **两套入口，一套 staging 机制** |
| 差异计算 | 复用 F3 已有的**逐字段 diff**（不是新机制，是把 F3 的通道从「文件」扩到「网页」） | 不重复造轮子 |
| 权限 | 录入者只能写自己的提案；**只有 `admin` 能采纳** | 界面层 + 接口层两道 |
| 同步 | 「同步」= **一次审核动作就把改动并入权威库** | 不引入分布式一致性 |
| 冲突 | 同一行被两人同时改 → staging 各存一份快照，审核页并排显示，**后提交者需重新确认** | 不自动合并 |
| 留痕 | 每条 staging 记录保留：proposer / 时间 / 字段级 diff / 审核人 / 审核意见 | 审核意见必填 |
| 审核页形态 | 抄 msyt 的「采集日志」页：时间 / 操作者 / 动作 / 条数 | 复用既有范式 |

**界面**

- 文献页「＋ 新增文献」/「✎ 编辑」→ 录入表单
- 导航「待审」（**仅 admin 可见**）：列表 + 左右对比（原值 vs 提案值，**只高亮有差异的字段**）+ 采纳/驳回
- 驳回要能写意见，提案人能看到

**验收**

| 编号 | 标准 |
|---|---|
| L2-1 | 普通用户提的提案**不能**直接改正式表（**查库确认**，不能只看界面） |
| L2-2 | 管理员采纳后：正式表变 + staging 变已审 + **图谱边数跟着变** |
| L2-3 | 驳回能写意见，提案人看得到 |
| L2-4 | 改 1 个字段，diff **只显示 1 行**差异（不是整行对比） |
| L2-5 | 同一行两人同时提 → 审核页**并排显示两份**，不自动合并 |

### 草稿 3 · 地图、时间线、统计图

**这三项难度差很大，必须拆开排。**

#### ③-a 统计图（纯代码，1 天）

现有总览已有 6 组分布（文献类型 / 语种 / 出版年份 / 数据来源类型 / 开放类型 / 时间分期标签）。

**新增**：
1. **交叉分析**：主题 × 年代、空间分区 × 文献类型、语种 × 标签
2. **标签共现矩阵**：哪些主题/空间标签常一起出现（这直接支撑「良渚文化的知识结构」）
3. 每张图：⬇PNG（2 倍分辨率） / ⬇CSV / ⬇**离线 HTML**（内联，断网双击可开）
4. **口径页脚必写**（抄 cacx）：像「各行相加会超过总数」这种必须写在图上

#### ③-b 时间线（1 天，但**必须先定口径**）

★ **两根轴不能混**：

| 轴 | 数据 | 性质 |
|---|---|---|
| **轴 1：文献出版年** | 1984–2026，200 条 | **确切值**，能做年度/年代趋势 |
| **轴 2：良渚文化分期** | 标签里的「早/中/晚期」「当代」「崧泽-良渚过渡」… | ★ **是分类，不是连续年代** |

**做法**：
- 时间线**默认轴 1**（出版年）
- 轴 2 做成**分期色带**（不是刻度轴），点击某期 → 列出该期的文献
- 良渚文化的绝对年代（约公元前 3300–2300 年）只能作为**背景参考带**标出，
  并写明「**文献的出版年与器物的年代是两回事**」
- **缺月补 0**（抄 cacx），否则趋势图会骗人

> ⚠ **绝不能**把「文献出版年」和「考古年代」画在同一根轴上——
> 那会把 2024 年发表的考古论文画到公元前。这是最容易犯、也最容易被老师当场抓住的错。

#### ③-c 地图（★ **数据先行**，代码 1.5 天 + 数据工作）

★ **我们没有经纬度。** 空间分区标签是**区域名**（良渚古城 / 姚江流域 / 环太湖 / 良渚遗址群 /
良渚博物院 / 跨遗址 / 参考案例…），**不是坐标**。所以地图必须分两层：

| 层 | 做什么 | 需要什么 | 何时能做 |
|---|---|---|---|
| **第一层：区域地图** | 把空间分区画成区域，点区域 → 列出该区域的文献 | 区域**边界**（GeoJSON 或简化的示意图） | ★ **现在就能做**（不需要坐标） |
| **第二层：遗址点位地图** | 每个遗址一个标记，点标记 → 列出涉及该点的文献 | 一张「良渚相关遗址**点位表**」（名称 + 经纬度 + 所属区域）+ **底图与坐标系方案（§4.5）** | 要**先补数据** |

**点位表从哪来（三步，都不用编）**：

1. **从现有数据拆出遗址名**：登记表的空间分区标签只能到区域；再从 MD 正文抽具体遗址名
   （莫角山 / 反山 / 瑶山 / 汇观山 / 钟家港 / 姜家山 / 官井头 / 卞家山 / 凤山 / 寺墩 /
   福泉山 / 广富林 / 草鞋山 / 马桥 / 马家浜 / 崧泽 / 河姆渡 / 钱山漾 …）
2. **坐标必须查证**（不能编）→ ★ **坐标格式与坐标系见 §4.5**
   （WGS84 / GCJ02 / BD09 别搞混，混用会偏**几百米**——对考古遗址是学术数据错位）
3. **做成可编辑的数据文件**（xlsx/CSV，随包分发），组内查证后填入；
   迁移时**算好三套坐标入库**，前端按底图选列（见 §4.5）

★ **界面必须标注**：「坐标为组内补充，非原始数据来源」。

> ⚠ **诚实的边界**：文献的「空间分区」是**这篇文献讨论的范围**，
> **不等于**「发掘就在这个点」。地图只能表达「**哪些文献谈到过这里**」，
> 不能表达「发掘就在这里」。这句话要写进界面和报告。

### 草稿 4 · 全文检索与 AI 问答（**最有价值**）

#### ④-a 全文检索增强（分词 + 领域词典）

**现状**：FTS5 trigram 是**子串匹配**——「玉琮」能查到，但不知道「良渚」和「良渚文化」是一回事。

**加两样**：
1. **jieba 分词 + 良渚领域词典**（用户词典文件，不是硬编码）
   → 词典初始条目：玉琮 / 玉璧 / 玉钺 / 神人兽面 / 刻符 / 莫角山 / 反山 / 瑶山 / 汇观山 /
   钟家港 / 姜家山 / 官井头 / 卞家山 / 寺墩 / 福泉山 / 广富林 / 草鞋山 / 马桥 / 马家浜 /
   崧泽 / 河姆渡 / 钱山漾 / 良渚 …
2. **新词发现**（抄 cacx 的「分词实验室」）：凝固度 + 邻字熵 → 出候选 → **人工勾选才进词典** →
   写完**立即生效、重启后仍在**
   - 对良渚语料特别有用：「玉琮」「神人兽面」「刻符」这类词通用分词会切碎
   - ★ **候选是候选不是结论，收不收由人定**（这条纪律要写在界面上）

**双模式切换**（抄 cacx）：
- 「整句精确」= 现在的 trigram 子串
- 「分词扩召回」= jieba 切词 → 多词组合

#### ④-b AI 问答（RAG，旁路）

**形态**：问题 → 检索 top-k 片段（MD 全文 + 原始 JSON 全文）→ 送 LLM → **带引用的回答**

★ **答案必须能点回原文**（引用带 `lit_id` + 页码/图号）——
这跟图谱「点边看原文」是**同一条纪律**：**没有引用的答案不上屏**。

**三条硬规矩**（抄 cacx 的做法）：

| 规矩 | 做法 | 原因 |
|---|---|---|
| **只预览不执行** | 默认只给草稿，点了才真调模型 | 防误触、防烧配额 |
| **密钥掩码** | 存 `config/settings.json`，保存后只显示「已配置（N 字符）」 | 密钥不进版本库、不回显 |
| **审查拦截如实显示** | LLM 返回「内容审查拦截」时**原样显示** | cacx 实测：**重试一万次也一样**，不是配置问题 |

**其他要点**：
- 引用溯源：回答里每个引用可点 → 跳详情页 → 定位到该文献/该图
- **失败兜底**：没有引用支撑的句子标「**未找到出处**」，**不与有引用的句子混在一起**
- ★ **底子比 cacx 当初好**：全文索引已具备（201 篇 MD + 202 份原始 JSON 全文），
  不需要先做「可检索文本」这一步
- 需要**你自己的 API key**（设置页配置，供应商/地址/模型/密钥，可粘贴其它工具的配置自动识别）

|---|---|

| 任务 | 内容 | 前置 | 人日 |
|---|---|---|---|
| **K1 Schema 落地** | 按 cnSchema 规范写「良渚 Schema v1.0」（实体类/关系类/属性/受控词表引用） | **教师词表** | 1.5 |
| **K2 抽取层** | **规则主干**（词典+模式，产出必带原文证据）＋ **OneKE 旁路**（只出候选） | K1 | 3 |

**K2 必须守的三条**（从 cacx《关系图谱内置化-解决方案》里抄的原则）：

1. **解析必须本地可复现**——同一份数据、同一份代码，永远抽出同样的结果。
   评审者可能追问「你这个数怎么来的」，你必须能当场重跑给他看。
2. **规则是主干，AI 是辅助**（质检与词典回流），不是反过来。
3. **每条关系必带原文证据**——没有证据的关系**不入库**。
   验收判据就一条：随机 10 条关系的原文句**能在原文里搜到**。

| # | 问题 | 严重度 | 修法 | 出处 |

| **B4** | **`/docs`（FastAPI 自带 Swagger）开着**，是一张完整接口地图 | 🟡 中（现在只本机，风险低；一旦挂公网就高） | 生产模式关掉 | msyt `SECURITY.md` 第 1 条 |
